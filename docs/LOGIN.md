# Вход в MAX, когда требуется капча

## Что происходит

Обычный вход по SMS-коду:

```bash
python -m maxbridge login
```

С некоторого момента MAX может ответить так:

```
Ошибка соединения с MAX: MAX вернул ошибку на opcode 17: captcha.validation-failed
```

Это значит, что MAX начал требовать капчу при запросе кода. Из консоли её не
пройти, и обходить её программно мы не будем: капчу должен решать человек.

Решение простое — **залогиниться в браузере руками**, а мосту отдать уже
выданный токен. Дальше мост работает как обычно: он умеет входить по токену,
запрос SMS-кода ему больше не нужен.

## Порядок действий

### 1. Войти в веб-клиент

Открой <https://web.max.ru> и залогинься как обычно: номер, SMS-код, капча.
Дождись, пока загрузится список чатов.

### 2. Открыть консоль браузера

`F12` → вкладка **Console**. Если Chrome ругается «Не вставляйте сюда код» —
набери `allow pasting` и нажми Enter, это разовая защита от мошенников.

### 3. Найти, где лежит токен

Вставь и выполни:

```js
Object.entries(localStorage)
  .filter(([k, v]) => /token|auth|device|session/i.test(k) || (typeof v === 'string' && v.length > 40))
  .forEach(([k, v]) => console.log(k, '→', v.length > 60 ? v.slice(0, 10) + '…(' + v.length + ' симв.)' : v));
```

Команда печатает **имена** ключей и обрезанные значения — токен целиком на
экран не выводится. Ищи два значения:

* длинную строку (обычно 40+ символов) в ключе со словом `token` или `auth` —
  это **токен**;
* строку вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` (UUID) — это **deviceId**.

Токен может лежать и внутри JSON — тогда значение начинается с `{`. В этом
случае разверни его: `JSON.parse(localStorage.getItem('имя_ключа'))`.

### 4. Скопировать значения

По одному, подставляя найденное имя ключа:

```js
copy(localStorage.getItem('ИМЯ_КЛЮЧА_С_ТОКЕНОМ'))
```

`copy()` кладёт значение в буфер обмена, не печатая его на экран.

### 5. Отдать мосту

```bash
python -m maxbridge login --token
```

Команда спросит токен (ввод скрыт, как пароль) и deviceId, сохранит сессию
и сразу проверит её: подключится к MAX и покажет, под каким номером вошла
и сколько чатов синхронизировалось. Если токен не подошёл — скажет об этом,
а не будет молча делать вид, что всё хорошо.

### 6. Проверить позже

```bash
python -m maxbridge login --verify
```

## Важное про deviceId

Токен выдаётся **конкретному устройству**, поэтому deviceId из браузера нужен
обязательно: со своим случайным UUID мост либо не войдёт, либо MAX сочтёт это
входом с нового устройства со всеми вытекающими. Берём ровно тот, что в
браузере.

Обратная сторона: браузерная вкладка и мост становятся одной сессией. Если в
приложении MAX завершить эту сессию, отвалятся оба.

## Если токен протух

Сессии MAX живут долго, но не вечно. Признак — мост в логах пишет, что не может
войти. Лечение то же самое: заново залогиниться в браузере и повторить шаги
3–5. Отдельного «продления» тут нет.

## Запасной вариант

Если возиться с токеном не хочется, есть официальный путь:

```
MAX_MODE=botapi
MAX_BOT_TOKEN=токен_бота_из_MAX
```

Работает без капчи и без серых зон, но бот увидит **только адресованные ему**
сообщения — упоминания, команды и личку боту. Всю переписку аккаунта в этом
режиме получить нельзя, это ограничение платформы.
