# Риски и правовая сторона

Документ написан честно: у инструмента есть режим, который формально выходит
за рамки условий сервиса. Решение принимаешь ты, но принимать его нужно
осознанно.

## Два режима — два уровня риска

### `MAX_MODE=botapi` — официальный путь

Используется опубликованный [Bot API MAX](https://dev.max.ru/docs-api).
Никаких серых зон. Ограничение платформы: бот получает только адресованные ему
сообщения — личку боту, упоминания, команды. Переписку аккаунта он не видит.

Дополнительно: с осени 2025 MAX разрешает публиковать ботов и мини-приложения
только верифицированным юридическим лицам РФ. Для внутреннего использования без
публикации это не мешает, для продажи готового бота — существенно.

### `MAX_MODE=userbot` — серая зона

Вход выполняется под аккаунтом живого человека через внутренний
WebSocket-протокол клиента MAX. Протокол не опубликован вендором, отреверсен
сообществом. Что это значит на практике:

- **Условия сервиса.** Автоматизация пользовательского аккаунта, скорее всего,
  нарушает пользовательское соглашение MAX. Возможная санкция — блокировка
  аккаунта. Гарантий, что этого не произойдёт, нет ни у кого.
- **Стабильность.** Вендор может поменять опкоды, схему авторизации или ввести
  проверку клиента в любой момент, без анонса. Мост перестанет работать до
  обновления кода.
- **Ответственность.** Авторы MaxBridge не несут ответственности за блокировку
  аккаунта, потерю данных и любые иные последствия. Пользуешься на свой риск.

Именно поэтому режим переключается одной строкой: если риск неприемлем,
переходи на `botapi` и живи с ограниченным охватом.

## Персональные данные

Мост сохраняет переписку в локальную базу SQLite (`data/maxbridge.db`) —
это нужно для поиска, сводок и радара незакрытых.

- База лежит **только на твоём сервере**. Никуда не отправляется.
- Если включён AI, тексты сообщений уходят в Anthropic API для классификации
  и составления сводок. Не включай AI, если по переписке есть обязательства
  о неразглашении, несовместимые с передачей текста стороннему обработчику.
- В переписке есть данные третьих лиц — собеседников. Если разворачиваешь мост
  в организации, это обработка персональных данных со всеми вытекающими
  (152-ФЗ): нужны основания обработки, срок хранения, порядок удаления.
- Для чистки истории достаточно удалить `data/maxbridge.db`.

## WhatsApp: тоже два пути

- **`cloud`** — официальный WhatsApp Business Cloud API. Легально, требует
  бизнес-аккаунта и верификации. Инициировать переписку вне 24-часового окна
  можно только одобренным шаблоном, иначе Meta вернёт ошибку 131047.
- **`waha`** — self-hosted мост к WhatsApp Web. Не требует верификации, но это
  тот же класс риска, что userbot в MAX: аккаунт могут заблокировать.

## SMS

Полностью легально. Единственное: рассылки по чужим номерам без согласия —
нарушение закона о рекламе. Здесь уведомления идут **на твой собственный номер**,
так что вопрос не возникает — но не переделывай это в рассылку клиентам.

## Что делать при блокировке сессии MAX

1. Останови мост.
2. Удали `data/max_session.json`.
3. Проверь аккаунт в приложении на телефоне.
4. Если аккаунт жив — `python -m maxbridge login` заново; если нет — переходи
   на `botapi`.
